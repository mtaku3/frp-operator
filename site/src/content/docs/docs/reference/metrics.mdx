frp-operator exposes Prometheus metrics at `/metrics` on the metrics port (default `:8443` when `metrics.service.enabled=true`). Metrics are served over HTTPS with bearer token authentication.

<Aside type="tip">
To enable scraping, see [Set up Prometheus scrape](../guides/prometheus-scrape).
</Aside>

## Controller-runtime standard metrics

frp-operator uses [controller-runtime](https://github.com/kubernetes-sigs/controller-runtime) as its reconciler framework. controller-runtime automatically registers the following metric families:

### Reconciler metrics

| Metric | Type | Labels | Description |
|---|---|---|---|
| `controller_runtime_reconcile_total` | Counter | `controller`, `result` | Total number of reconciliations by controller name and result (`success`, `error`, `requeue`, `requeue_after`) |
| `controller_runtime_reconcile_errors_total` | Counter | `controller` | Total number of reconciliation errors |
| `controller_runtime_reconcile_time_seconds` | Histogram | `controller` | Latency of reconciliations per controller |
| `controller_runtime_max_concurrent_reconciles` | Gauge | `controller` | Maximum concurrent reconciles configured per controller |
| `controller_runtime_active_workers` | Gauge | `controller` | Number of actively running reconcile goroutines |

The `controller` label takes one of these values for frp-operator:

- `exitclaim` — ExitClaim lifecycle controller
- `exitpool-hash` — pool template hash stamper
- `exitpool-counter` — pool exit count updater
- `exitpool-readiness` — pool readiness condition
- `exitpool-validation` — pool spec validation
- `disruption` — disruption controller
- `emptiness` — emptiness condition tracker
- `servicewatcher` — Service → Tunnel translator
- `servicewatcher-reversesync` — Tunnel → Service ingress reverse-sync
- `providerclass-hash` — ProviderClass spec hash stamper

### Work queue metrics

| Metric | Type | Labels | Description |
|---|---|---|---|
| `workqueue_adds_total` | Counter | `name` | Total items added to the work queue |
| `workqueue_depth` | Gauge | `name` | Current depth of the work queue |
| `workqueue_queue_duration_seconds` | Histogram | `name` | Time items spend in the queue before processing |
| `workqueue_work_duration_seconds` | Histogram | `name` | Time spent processing items |
| `workqueue_retries_total` | Counter | `name` | Number of retries for queue items |
| `workqueue_longest_running_processor_seconds` | Gauge | `name` | Duration of the longest running processor |

### REST client metrics

| Metric | Type | Labels | Description |
|---|---|---|---|
| `rest_client_requests_total` | Counter | `code`, `host`, `method` | Total HTTP requests made to the Kubernetes API server |
| `rest_client_request_duration_seconds` | Histogram | `host`, `method` | Latency of HTTP requests to the API server |

### Leader election

| Metric | Type | Labels | Description |
|---|---|---|---|
| `leader_election_master_status` | Gauge | `name` | `1` when this pod is the leader, `0` otherwise |

### Process and Go runtime

| Metric | Type | Description |
|---|---|---|
| `process_cpu_seconds_total` | Counter | Total CPU seconds used by the process |
| `process_open_fds` | Gauge | Open file descriptors |
| `process_resident_memory_bytes` | Gauge | Resident memory size |
| `go_goroutines` | Gauge | Number of goroutines |
| `go_gc_duration_seconds` | Summary | GC pause durations |

## Custom operator metrics

frp-operator does not currently register custom Prometheus metrics beyond the controller-runtime defaults. Operator-specific state is observable via Kubernetes object status fields:

| What to observe | Where to look |
|---|---|
| Number of active exits per pool | `ExitPool.status.exits` |
| Pool resource usage | `ExitPool.status.resources` |
| Tunnel phase distribution | `kubectl get tunnel -A -o jsonpath='{.items[*].status.phase}'` |
| Liveness failure count | `ExitClaim` annotation `frp.operator.io/liveness-failures` |
| Disruption events | `kubectl get events --field-selector reason=Drifted,Expired,Empty` |

<Aside type="tip">
Custom metrics for disruption counts, provisioning latency, and liveness probe outcomes are planned. Until then, use `controller_runtime_reconcile_total{controller="disruption"}` and reconcile latency histograms as a proxy.
</Aside>

## Useful PromQL queries

**Reconciliation error rate by controller:**
```promql
rate(controller_runtime_reconcile_errors_total[5m])
```

**p99 reconciliation latency for the lifecycle controller:**
```promql
histogram_quantile(0.99, rate(controller_runtime_reconcile_time_seconds_bucket{controller="exitclaim"}[5m]))
```

**Is this pod the active leader?**
```promql
leader_election_master_status{name="frp-operator.frp.operator.io"}
```

**API server request rate:**
```promql
rate(rest_client_requests_total[5m])
```

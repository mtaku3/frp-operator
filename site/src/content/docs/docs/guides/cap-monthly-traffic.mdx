**Goal:** Prevent unbounded cloud egress costs by setting a monthly traffic ceiling on a pool. The operator stops provisioning new ExitClaims once the aggregate traffic across the pool approaches the cap.

## How limits work

`ExitPool.spec.limits` is a resource list (same shape as a Kubernetes `ResourceList`). The operator tracks per-pool resource usage and refuses to provision new exits when any limit would be exceeded. Recognized limit keys:

| Key | Unit | What it caps |
|---|---|---|
| `cpu` | millicores | Aggregate CPU capacity across exits |
| `memory` | bytes (k8s quantity) | Aggregate memory capacity |
| `frp.operator.io/exits` | count | Number of ExitClaims |
| `frp.operator.io/bandwidthMbps` | Mbps | Aggregate bandwidth |
| `frp.operator.io/monthlyTrafficGB` | GB | Aggregate monthly traffic budget |

When a limit is reached, new Tunnel requests are held in `phase: Allocating` with reason `LimitsExceeded` until capacity is freed (e.g. another claim is removed or traffic resets).

## Apply

```yaml
apiVersion: frp.operator.io/v1alpha1
kind: ExitPool
metadata:
  name: budget-pool
spec:
  template:
    spec:
      providerClassRef:
        group: frp.operator.io
        kind: DigitalOceanProviderClass
        name: do-provider
      requirements:
        - key: topology.kubernetes.io/region
          operator: In
          values: ["nyc3"]
        - key: node.kubernetes.io/instance-type
          operator: In
          values: ["s-1vcpu-1gb"]
      frps:
        version: "v0.61.1"
        bindPort: 7000
        adminPort: 7400
        allowPorts: ["1024-65535"]
        auth:
          method: token
  limits:
    frp.operator.io/exits: "5"
    frp.operator.io/monthlyTrafficGB: "500"
```

## Verify

Check the pool's status to see current usage against limits:

```bash
kubectl get exitpool budget-pool -o yaml | grep -A 10 status
```

The `status.resources` field mirrors the aggregate resource usage:

```yaml
status:
  exits: 3
  resources:
    frp.operator.io/monthlyTrafficGB: "187"
```

Check if any Tunnel is blocked:

```bash
kubectl get tunnels -o custom-columns=\
  NAME:.metadata.name,\
  PHASE:.status.phase,\
  REASON:.status.conditions[0].reason
```

A blocked Tunnel shows:

```
NAME              PHASE       REASON
new-tunnel        Allocating  LimitsExceeded
```

## Notes / gotchas

- `frp.operator.io/monthlyTrafficGB` is a **provisioning gate**, not a network-layer enforcement. The operator will not provision new exits beyond the cap, but it cannot block traffic on an already-provisioned exit that exceeds its allocation. Use your cloud provider's Droplet bandwidth alerts for hard enforcement.
- Traffic accounting depends on the operator receiving actual usage data from the frps admin API. If the admin API is unreachable (liveness failure), the operator uses the last-known value. See [Liveness probing](../concepts/liveness).
- Limits apply **per pool**. To cap total spend across multiple pools, set limits on each pool individually.
- Setting `frp.operator.io/exits: "1"` combined with `consolidationPolicy: WhenEmpty` creates a single-exit pool: one exit at a time, deleted when empty.

<Aside type="tip">
Combine `frp.operator.io/exits` with `expireAfter` for predictable cost: cap the count and rotate on schedule so old exits are replaced rather than accumulated.
</Aside>

**Goal:** Expose the frp-operator metrics endpoint and configure Prometheus Operator to scrape it automatically via a `ServiceMonitor`.

## Prerequisites

- [Prometheus Operator](https://github.com/prometheus-operator/prometheus-operator) installed in your cluster
- frp-operator installed (see [Install for production](../getting-started/install-production))

## Steps

<Steps>

1. **Enable the metrics Service and ServiceMonitor**

   The metrics service is disabled by default. Enable it along with the `ServiceMonitor`:

   ```bash
   helm upgrade frp-operator \
     oci://ghcr.io/mtaku3/charts/frp-operator \
     --namespace frp-operator-system \
     --reuse-values \
     --set metrics.service.enabled=true \
     --set metrics.service.port=8443 \
     --set metrics.serviceMonitor.enabled=true \
     --set metrics.serviceMonitor.interval=30s \
     --set metrics.serviceMonitor.scrapeTimeout=10s \
     --set "metrics.serviceMonitor.additionalLabels.release=prometheus"
   ```

   The `additionalLabels.release=prometheus` label must match your Prometheus Operator's `serviceMonitorSelector`. Check your Prometheus CR:

   ```bash
   kubectl get prometheus -A -o jsonpath='{.items[*].spec.serviceMonitorSelector}'
   ```

2. **Verify the ServiceMonitor was created**

   ```bash
   kubectl -n frp-operator-system get servicemonitor
   ```

   The rendered `ServiceMonitor` looks like this:

   ```yaml
   apiVersion: monitoring.coreos.com/v1
   kind: ServiceMonitor
   metadata:
     name: frp-operator
     namespace: frp-operator-system
     labels:
       app.kubernetes.io/name: frp-operator
       release: prometheus
   spec:
     selector:
       matchLabels:
         app.kubernetes.io/name: frp-operator
     namespaceSelector:
       matchNames:
       - frp-operator-system
     endpoints:
     - port: https-metrics
       path: /metrics
       scheme: https
       interval: 30s
       scrapeTimeout: 10s
       bearerTokenFile: /var/run/secrets/kubernetes.io/serviceaccount/token
       tlsConfig:
         insecureSkipVerify: true
   ```

3. **Verify the metrics endpoint is reachable**

   Port-forward the metrics service and curl the endpoint:

   ```bash
   kubectl -n frp-operator-system port-forward svc/frp-operator 8443:8443
   curl -sk https://localhost:8443/metrics | head -20
   ```

4. **Check Prometheus targets**

   In the Prometheus UI, go to **Status → Targets** and search for `frp-operator`. The target should appear as `UP`.

</Steps>

## Available values

| Value | Default | Description |
|---|---|---|
| `metrics.service.enabled` | `false` | Create a Service exposing port 8443 |
| `metrics.service.port` | `8443` | Port on the Service |
| `metrics.service.type` | `ClusterIP` | Service type |
| `metrics.serviceMonitor.enabled` | `false` | Create a ServiceMonitor |
| `metrics.serviceMonitor.interval` | `30s` | Prometheus scrape interval |
| `metrics.serviceMonitor.scrapeTimeout` | `10s` | Prometheus scrape timeout |
| `metrics.serviceMonitor.additionalLabels` | `{}` | Extra labels for ServiceMonitor selector matching |
| `metrics.serviceMonitor.relabelings` | `[]` | Prometheus relabel rules |
| `metrics.serviceMonitor.metricRelabelings` | `[]` | Prometheus metric relabel rules |

<Aside type="tip">
For the available metrics and their labels, see the [Metrics reference](../reference/metrics).
</Aside>

## Notes / gotchas

- The metrics endpoint uses HTTPS with the controller's serving certificate. The ServiceMonitor sets `insecureSkipVerify: true` by default. If your Prometheus enforces certificate validation, replace this with a proper `caFile` reference.
- Enabling `networkPolicy.enabled=true` restricts ingress. You must also set `networkPolicy.prometheusNamespace` to allow the Prometheus pods to reach port 8443. See [Enable NetworkPolicy for metrics](./metrics-networkpolicy).
- `metrics.serviceMonitor.enabled=true` fails with a Helm error if `metrics.service.enabled=false`. Always enable the Service before or alongside the ServiceMonitor.

In the releases section of the documentation, you can find the release notes and upgrade instructions for each release of frp-operator. It also contains information on breaking changes between each release and things to look out for when upgrading.

<Aside type="note">
  Before performing upgrades of frp-operator, it is advised to take a backup of all your frp-operator resources just in case an issue occurs whilst upgrading.
</Aside>

We recommend that you upgrade frp-operator one minor version at a time, always choosing the latest patch version for the minor version. You should always read the release notes for the minor version to which you are upgrading. In cases where a large version jump is needed to get an installation up to date, it may be possible to do a full uninstall and re-install of frp-operator without application downtime and/or unnecessary disruption, however we do not guarantee that this will work for your particular setup — see [Reinstalling frp-operator](/docs/installation/reinstall/).

## Upgrading with Helm

If you installed frp-operator using Helm, you can easily upgrade using the Helm CLI.

<Aside type="note">
  Before upgrading, please read the relevant release notes for your from and to version.
</Aside>

Once you have read the relevant upgrading notes and taken any appropriate actions, you can begin the upgrade process — replacing `<version>` with the version number you want to install.

<Aside type="note">
  You can find out your release names using `helm list -n frp-operator`.
</Aside>

### CRDs managed using the CRD chart

If you installed the CRD chart (the recommended approach), upgrade it first so that new CRD schemas are available before the operator starts:

```bash
helm upgrade --reset-then-reuse-values \
  --version <version> frp-operator-crd oci://ghcr.io/mtaku3/charts/frp-operator-crd
```

Then upgrade the operator chart:

```bash
helm upgrade --reset-then-reuse-values \
  --version <version> frp-operator oci://ghcr.io/mtaku3/charts/frp-operator
```

### CRDs managed separately

If you are managing CRDs separately (for example via the `helm template` output described in the [Helm installation guide](/docs/installation/helm/#output-yaml)), you should upgrade your CRD resources first:

```bash
helm template frp-operator-crd oci://ghcr.io/mtaku3/charts/frp-operator-crd \
  --namespace frp-operator \
  --version <version> | kubectl apply -f -
```

And then upgrade the Helm chart:

```bash
helm upgrade --reset-then-reuse-values \
  --version <version> frp-operator oci://ghcr.io/mtaku3/charts/frp-operator
```

### Upgrading from the Legacy Helm Repository

frp-operator only publishes via the OCI registry; there is no legacy HTTP Helm repository. This section does not apply.

## Upgrading using static manifests

If you installed frp-operator using `helm template` output applied with `kubectl`, you can upgrade them in a similar way to how you first installed them.

<Aside type="note">
  Before upgrading, please read the relevant release notes for your from and to version.
</Aside>

Once you have read the relevant notes and taken any appropriate actions, you can begin the upgrade process — replacing `<version>` with the version number you want to install:

```bash
helm template frp-operator-crd oci://ghcr.io/mtaku3/charts/frp-operator-crd \
  --namespace frp-operator \
  --version <version> | kubectl apply -f -

helm template frp-operator oci://ghcr.io/mtaku3/charts/frp-operator \
  --namespace frp-operator \
  --version <version> | kubectl apply -f -
```

## Reinstalling frp-operator

In some cases there may be a need to do a full uninstall and re-install of frp-operator. An example could be when a very old frp-operator version needs to be brought up to date and it isn't feasible to upgrade one minor version at a time, which is our default recommended upgrade strategy.

See [Reinstalling frp-operator](/docs/installation/reinstall/) for a full guide on how to do this without any issues.
